# 自动化市场发现

本文档解释了 Claude Code Marketplace Hub 如何自动从 GitHub 发现和收集新的插件市场。

## 概述

市场中心使用自动化发现系统在 GitHub 上查找包含 Claude Code 插件市场的仓库。该系统定期运行，确保中心与不断增长的生态系统保持同步。

## 工作原理

### 1. GitHub 代码搜索

发现脚本在 GitHub 上搜索包含 `.claude-plugin/marketplace.json` 文件的仓库。这是 Claude Code 市场清单的标准位置。

**搜索查询：**
```
path:.claude-plugin/marketplace.json
```

### 2. 验证

对于每个发现的仓库，脚本会：

1. **获取清单文件** 从 GitHub raw URL
2. **验证结构** 确保必需字段存在：
   - `name`: 市场标识符
   - `plugins`: 插件条目数组
3. **检查插件数量** 确保市场有实际内容
4. **验证可访问性** 尝试获取清单以验证

### 3. 条目创建

有效的市场会自动转换为市场条目，包含：

- **ID**: 从仓库名称生成（例如：`username/repo` → `username-repo`）
- **名称**: 仓库全名
- **描述**: 来自清单或仓库描述
- **所有者**: 仓库所有者信息
- **仓库 URL**: GitHub 仓库链接
- **清单 URL**: marketplace.json 文件的直接链接
- **标签**: 初始标记为 `community`
- **已验证**: 设置为 `false`（需要手动验证）
- **添加日期**: 当前日期

## 手动运行发现

### 前置条件

- Node.js 20+
- Yarn 包管理器
- GitHub 个人访问令牌（用于 API 访问）

### 本地执行

1. **设置环境：**

```bash
export GITHUB_TOKEN=your_github_token_here
```

2. **试运行（仅预览）：**

```bash
yarn discover
```

这将：
- 在 GitHub 上搜索市场
- 验证发现的市场
- 生成预览文件：`discovered-marketplaces.json`
- 不修改实际市场列表

3. **保存发现：**

```bash
yarn discover:save
```

这将实际添加发现的市场到 `.claude-plugin/marketplaces.json`。

### 命令选项

- `--no-dry-run`: 禁用试运行模式并保存更改
- `--max=N`: 限制搜索结果（默认：100）

示例：
```bash
yarn discover --max=50
```

## 自动化工作流

发现过程通过 GitHub Actions 自动运行。

### 计划

- **每周**: 每周一 00:00 UTC
- **手动**: 可通过 GitHub Actions UI 触发

### 工作流步骤

1. **搜索和验证**: 查找并验证新市场
2. **创建 PR**: 如果发现新市场，自动创建 PR
3. **审查**: 维护者审查并合并 PR

### 手动触发

您可以从 GitHub 手动触发工作流：

1. 转到仓库的 **Actions** 标签
2. 选择 **"Discover New Marketplaces"** 工作流
3. 点击 **"Run workflow"**
4. 选择选项：
   - **Dry run**: 预览而不创建 PR
   - **Max results**: 限制结果数量

## 质量保证

### 自动检查

发现脚本执行多项自动检查：

- ✅ 有效的 JSON 结构
- ✅ 必需字段存在
- ✅ 清单可访问
- ✅ 不在市场列表中

### 人工审查

发现的市场在添加之前需要人工审查：

1. **清单质量**: 检查插件描述和元数据
2. **仓库健康**: 验证活跃维护
3. **无重复**: 确保无重复条目
4. **无垃圾**: 过滤低质量或垃圾仓库

## 排除仓库

如果某个仓库不应包含在自动发现中，维护者可以：

1. **添加到排除列表**（待实现）
2. **标记为已审查** 以在将来运行中跳过
3. **关闭自动 PR** 并说明原因

## 隐私和道德

发现系统：

- ✅ 仅搜索 **公共** 仓库
- ✅ 遵守 GitHub API 速率限制
- ✅ 不收集私人数据
- ✅ 在添加之前验证清单可访问性
- ✅ 允许仓库所有者选择退出

## 故障排除

### 速率限制

如果遇到速率限制错误：

1. 确保正确设置 `GITHUB_TOKEN`
2. 使用具有适当权限的令牌
3. 减少 `--max` 参数
4. 等待速率限制重置

### 无效清单

拒绝的常见原因：

- 缺少必需字段（`name`、`plugins`）
- 无效的 JSON 语法
- 清单不在正确路径
- 网络/可访问性问题

## 常见问题解答

**问：这个项目是主动收集、爬取 GitHub 上现有的 marketplace 吗？**

答：是的！本项目现在实现了自动化发现系统，可以：
- 🔍 主动搜索 GitHub 上的 Claude Code 插件市场
- 🤖 自动验证和收集符合标准的市场
- ⏰ 每周定期运行以发现新市场
- 📝 自动创建 PR 供人工审查
- ✅ 确保质量和安全标准

虽然系统是自动化的，但所有新发现的市场都需要经过人工审查才会被最终添加，以确保质量和合规性。
